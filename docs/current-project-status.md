# Current Project Status

Snapshot date: 2026-07-17

## Current State

- The project has a Web/API implementation for an online stock-selection Agent, AlphaSift screening, industry board data integration, and a vn.py-style paper trading page.
- The paper trading path works without a real vn.py installation by using the local Portfolio ledger; `vnpy_available=false` does not block local paper trading.
- Automatic paper trading can run from AlphaSift candidates through risk checks into local paper orders, with dry-run, manual approval, `paper`, and optional `vnpy_paper` execution modes.
- Agent run details now support persisted human acceptance feedback (`approved`, `needs_changes`, or `rejected`) with reviewer and notes. Feedback appears in the run list, detail timeline, and daily summary, and is carried into later same-strategy/market run context. A deterministic cross-market objective can use needs-changes/rejected feedback, consecutive failures, or degraded cross-run quality to tighten candidate count and per-order cash; it never widens saved limits or bypasses risk gates.
- Runtime scheduler background tasks are registered independently from the daily analysis job, so `serve-only` / `webui-only` can still run paper auto-trading tasks.
- Runtime scheduler reconcile now reuses process-local locks by task name. A replacement generation records a persisted `task_already_running` skip while the older generation finishes, status exposes `overlap_guarded` and `previous_generation_running`, and exception paths release the lock for the next run.
- The API-owned vn.py MainEngine/EventEngine is now injected into Runtime scheduler paper-trading services; the recovery task runs once at registration and then every one to five minutes, so background execution no longer has a separate bridge capability from Web requests.
- vn.py runtime connection diagnostics now distinguish a returned `MainEngine.connect()` request from a gateway-confirmed connection. Connect exceptions degrade to `connect_failed` without aborting API startup, supported gateway hooks refresh on status reads, and an explicitly disconnected gateway blocks new submissions as `vnpy_gateway_disconnected`.
- vn.py runtime now has an opt-in unattended reconnect monitor. It retries only explicit failed/disconnected states at a configurable 5-to-3600-second base interval, rereads the external settings file for each attempt, exponentially backs off consecutive failures to a configurable maximum, and resets after confirmed recovery. A configurable 5-to-600-second confirmation grace period protects accepted asynchronous connections. Diagnostics expose thread state, grace, base/current/maximum intervals, consecutive failures, attempt/success/failure counts, timestamps, last result, and next check without exposing credentials.
- Operators can request one safe reconnect through `POST /api/v1/vnpy-paper/gateway/reconnect` or the Web paper-trading toolbar even when background auto reconnect is disabled. Connected, confirmation-pending, and grace-protected gateways are not logged in again; the action returns connection/reconnect audit only and does not create an Agent run, plan, or order.
- Reconnect transitions now use a separate event queue: the first consecutive failure, first maximum-backoff transition, and recovery persist into the existing `vnpy_paper` alert history and notification route. Repeated failures do not duplicate the open event, recovery is recorded as resolved, shutdown drains queued events, and diagnostics exclude the connection path and credentials.
- The built-in gateway now has default-off deterministic rejection and duplicate-trade-event injection for acceptance testing. The installer fault matrix proves one native rejection produces no trade, two callbacks with the same `vt_tradeid` remain one MainEngine/Portfolio trade, and reconnect faults can be composed in the same real vn.py runtime. Native Chinese vn.py status values are normalized, and an immediate post-persistence terminal reconciliation closes the race where a synchronous gateway event arrives before the Agent plan stores its `vt_orderid`.
- A real MainEngine/EventEngine Agent matrix now submits three candidates through one run and proves `filled / failed / filled` isolation under every-second-order rejection and duplicate trade callbacks. Final run counts are rebuilt from persisted plans after completion, and a concurrent duplicate callback that loses the Portfolio uniqueness race is treated as a successful idempotent no-op.
- Candidate-level missing prices now fail closed only after the independent realtime quote fallback also fails. The skipped result preserves requested-price, resolution-source, candidate-context, and budget audit. A real MainEngine/EventEngine three-candidate matrix proves the unavailable middle quote never reaches the gateway while the first and third candidates still fill exactly once.
- Candidate-context health now persists aggregate quote/fund-flow/news status plus provider-level `quote/<provider>`, `fund_flow/<provider>`, and `news/<provider>` trend evidence. Provider rows are excluded from the current-run quality score to prevent double weighting. Automatic Agent screening combines the latest 30-day same-strategy/market degradation rates with current source state, passes request-scoped fund-flow and news provider orders only to candidate enrichment, and isolates their caches without mutating global source priority. News evidence records every attempted provider, including exceptions followed by successful fallback. News providers now share the persisted 3-failure/5-minute/one-probe circuit-breaker contract used by realtime and fund-flow sources; empty usable results are inconclusive rather than transport failures.
- A generic no-order gateway soak CLI now reads the configured external `VNPY_*` runtime, samples connection state, counts order/trade/account/position events, records transitions and reconnect totals, and exits nonzero for insufficient connected ratio or missing required events. It suppresses the DSA business event bridge and never emits the settings path or payload. An explicit DSA_SIM-only disconnect mode validates the harness without making it available against real gateways.
- A complete isolated Python 3.13.14 environment now contains AlphaSift 0.2.0, LiteLLM 1.91.3, vn.py 4.4.0, and the project dependencies. Its smoke check constructs a real vn.py `OrderRequest`, starts and closes the real EventEngine/MainEngine, and uses the repository-local ignored `.vntrader/` runtime directory.
- Active vn.py plans become eligible for `MainEngine.get_order` / `get_all_trades` reconciliation after a 60-second grace period. Pausing new automatic buys keeps order recovery scheduled, and missed, cancel-race, or post-timeout late fills are still accumulated idempotently into the Portfolio ledger.
- The latest scheduler alignment fix delays the first `vnpy_paper_auto_trade` run to the next trading window when the time gate is enforced and the service starts outside market hours.
- Paper-trading budgets, cash checks, position exposure, and daily usage now use the account base currency. Foreign-market orders convert through the Portfolio FX table, fail closed for new buys when rates are missing or more than seven calendar days old, preserve sell-side risk reduction, and record both base and quote amounts for audit.
- Automatic holding age now pages through complete trade and split histories under the service's 100-row limit and replays open FIFO lots with corporate actions ordered before same-day trades, so a full exit followed by re-entry resets max-holding and no-progress clocks. Unavailable split history leaves age unknown instead of triggering a time-based exit from incomplete evidence. Risk-reducing sells remain recorded in orders, plans, decisions, and run counts when later data-quality, account, or market gates block new buys.
- Agent-run detail now derives a live `portfolio_change` audit from persisted plans backed by Portfolio trade IDs. Both Web detail views, timeline, and JSON export group booked buy/sell/net quantities and notionals by symbol while keeping submitted, unbooked order-level partial fills, dry runs, and approval-only plans visibly pending or planned. Partial, late, approved, and recovered fills appear automatically after ledger booking without persisting a duplicate account snapshot.
- Candidate decisions now persist `strategy_evidence`, `position_plan`, `risk_review`, `agent_review`, and `llm_review` in dedicated columns and expose them as top-level API fields. Order lifecycle callbacks preserve these explanations even when replacing `order_result`; startup migrates existing databases, and legacy rows/Web contracts keep a compatible embedded fallback.
- Automated buys now have default-off intraday and cross-market risk gates. The local gate audits equal-weight directional index changes and, for A shares, live advance/decline breadth; the linked gate uses a versioned market map and excludes VIX. Missing enabled evidence fails closed, sell-side risk reduction still runs first, and the Web exposes all thresholds. Provider quotes do not yet share a uniform as-of timestamp, so production time-alignment calibration remains open.
- Intraday/cross-market evidence calls now have a 15-second per-call budget and a process-wide cap of four outstanding worker threads. Timeouts, provider failures, and exhausted slots produce distinct audited evidence and fail closed without allowing an enabled buy gate to hang indefinitely or spawn unbounded workers.
- Explicit stock and industry target weights now cap each automatic buy to the remaining target gap instead of rejecting the whole candidate. Existing positions can be replenished toward an explicit stock target even when the maximum position count is reached or existing positions are normally skipped; the final amount is reduced to an executable market lot and audited in `target_weight_sizing`.
- Automatic buys now have an optional constrained portfolio-allocation stage with score-weighted, score/inverse-20-day-volatility, correlation-capped, and covariance target-tracking methods. Point-in-time local trailing returns drive the risk methods; missing history or overlap fails closed, and audits include observations, pairwise coefficients or covariance matrices, target vectors, convergence state, caps, intended budget, and executable A-share-lot residual.
- Every AlphaSift auto-trade run now receives a deterministic 0-100 data-quality score weighted by screen integrity (45%), candidate coverage (35%), and observed source health (20%). Source health now includes snapshot/daily providers and independently observed candidate-context quote, fund-flow, and news retrieval. Missing telemetry is marked unobserved at 70 rather than assumed healthy. `auto_min_data_quality_score` defaults to 60, including for missing or `null` legacy values; lower-scoring rounds are blocked as `data_quality_score_below_threshold`, while an explicit 0 keeps soft scoring audit-only without bypassing hard stale/unavailable gates. Candidate rule reviews also carry their own coverage score.
- Candidate missing fields now fail closed when they are required by an enabled buy-side control: an explicitly missing trading status blocks ST/suspension/price-limit evaluation as `candidate_trading_status_unavailable`, and unavailable turnover blocks a configured minimum-turnover check as `liquidity_data_unavailable`. Other missing fields remain scored and audited rather than being rejected indiscriminately.
- The Agent console now runs an on-demand 1/5/10/20-trading-day forward evaluation for persisted buy candidates. It anchors on the recorded decision price, reads only local daily bars strictly later than the decision date, reports coverage and return/excursion metrics, and never reruns a strategy or places an order by default.
- The same forward evaluation now joins persisted rule and LLM review snapshots, including real `action=skip` risk rejections, and builds a long-horizon quality matrix by reviewer/model plus prompt/evaluator version. It reports mature coverage, passed precision, blocked-loss avoidance, passed/blocked average returns, and return spread without treating missing forward bars as success.
- Cross-run quality now derives one effective verdict per candidate with LLM-over-rule precedence. Mature low passed precision or blocked-loss avoidance can make the combined state `blocked`; negative passed return or return spread can make it `guarded`. The existing opt-in gate consumes that combined state, while the always-on market objective can only tighten from it; insufficient evidence remains audit-only.
- Cross-run quality now also computes the versioned `candidate-return-risk-v1` objective from strictly forward candidate daily returns. It exposes daily mean return, volatility, downside deviation, 20% expected shortfall, horizon-scaled downside risk, maximum adverse excursion, and a deterministic utility score. Negative mature utility tightens candidate count and order cash; negative utility plus negative average return becomes `blocked`. The opt-in gate still affects buys only, while sell-side risk reduction runs first.
- Persisted return/risk objective snapshots now have a read-only 1-90-day calibration-trends API and a 7/30/90-day Web view grouped by market, strategy, and objective version. It reports observation coverage, states, mature samples, and utility without claiming overlapping rolling windows as independent samples; legacy runs remain `unknown`.
- AlphaSift now has a persisted point-in-time factor snapshot table and single-date replay APIs. Hard-filter and scoring-field coverage are audited separately, incomplete datasets fail closed, and the Agent console can inspect coverage and run deterministic hard-filter plus `screen_score` replay without current-data fallback or LLM ranking.
- For an explicitly supplied historical universe, a bounded background task now collects AKShare daily/turnover and historical valuation factors with strict as-of dates. The Agent console can then run a cross-date equal-weight or explicit per-symbol target-weight portfolio backtest with per-side costs, benchmark/excess return, drawdown, coverage, and period equity; residual target weight stays in cash and it never places orders.
- Cross-date backtests now retain symbols selected in adjacent snapshots, charge costs only on actual entries/exits, expose period and aggregate turnover, and apply A-share suspension/price-limit gates only when a trade is required.
- A sell blocked by suspension or a limit-down session is now marked to market without fake sell costs and carried into the next rebalance attempt. Period output separates selected coverage from actual/forced holdings, and summary metrics disclose any ending open positions.

Lease-protected force takeover prevents an old executor from advancing a replaced job, and the Agent console restores the latest job after refresh.
- Portfolio replay now defaults through API/Web to a cash ledger: equal target values or explicit per-symbol equity percentages are converted to whole A-share lots, overweight positions sell before underweight buys, buys are capped by cash, and final blocked exits remain marked open positions. Explicit weights total at most 100%, preserve the residual as cash, apply only to configured symbols also selected in that period, and audit configured-but-unselected symbols. Period output audits cash, market value, quantities, target weights, trades, blocks, and traded-notional turnover; the prior mean-return approximation remains opt-in and rejects explicit weights.

The same absolute fee function constrains target and cash-affordable lot quantities, while every trade and period plus aggregate metrics disclose execution price, commission, tax, slippage cost, and net cash effect. Defaults remain zero because broker schedules and historical tax regimes are not inferred.
- Cash-ledger replay now accepts explicit cash-dividend and split-adjustment events against unadjusted prices. Per-symbol event clocks advance to trade/mark dates, same-day actions run before trades, dividends apply only to existing shares, and splits update quantities before rebalancing or final exit. Period audits distinguish applied from not-held events and expose share/cash effects; fractional shares settle only when the event provides an explicit cash-in-lieu price and otherwise fail closed.

Invalid, incomplete, or timed-out ranking falls back immediately to deterministic `screen_score`. A cross-run circuit opens after the configured consecutive failures, skips LLM during cooldown, and permits exactly one shorter half-open recovery probe. Its five-minute lease blocks duplicate probes but converts an abandoned probe into a failure instead of locking recovery permanently; success closes the circuit and failure starts a new cooldown. Three consecutive exceptions per market/provider open a five-minute cooldown, later sources continue serving requests, and one half-open probe determines recovery. Symbol-specific empty quotes do not poison provider health. Agent diagnostics persist the state, failure count, remaining cooldown, and sanitized error under candidate-context source routing, and the console renders the actual route state.

THS stock/industry fields are normalized from CNY 10K to CNY, the ten-day value is derived from the latest ten daily net amounts, and missing token/permission/data transparently falls back without failing screening. Exceptions use the same persisted three-failure/five-minute/single-probe recovery state as quotes. AlphaSift status, Agent run diagnostics, and the Web source-routing panel expose both providers. Provider state now lives in `provider_source_health.json`; the previous realtime-only file is read and migrated automatically.
- Candidate decisions now persist a versioned `strategy_evidence` contract in both decision and trade-plan order audits. It records the effective strategy, rank, screen/final scores, bounded upstream rule matches, factor decomposition, rationale, and LLM overlay without inferring missing matches. Evidence is `detailed`, `summary_only`, or `unavailable`; the Agent console renders the same state and remains compatible with legacy runs.
- Automated allocation now offers `target_tracking_min_variance_20d`: it builds a point-in-time annualized covariance matrix from overlapping local trailing returns, tracks arbitrary remaining position-target gaps (or candidate-score targets), applies a configurable variance penalty, and then passes the optimized weights through the existing cash, exposure, industry, order-slot, and lot constraints. Missing covariance history fails closed; Agent audits expose the target vector, matrix, convergence, penalty, and final weights.
- The consecutive-failure fuse remains latched, but it now supports an opt-in persisted cooldown. When enabled, the first open timestamp survives restarts, the due run is released as a single recovery probe, and another failed probe starts a fresh fuse cycle. Manual reset remains available, status exposes the recovery deadline, and automatic releases create an auditable `failure_fuse_auto_recovered` system event.
